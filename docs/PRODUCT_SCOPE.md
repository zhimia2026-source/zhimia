# ZHI 产品范围：聊天系统优先

## 决策
- 智能人聊天系统是主入口；不再开发智能人观察台作为独立主产品。
- 复用现有聊天 UI、消息流和历史记录接口，先审计再修改，不重做同类功能。
- 本仓库的 Python MVP 保留为本地验证工具，不替代现有聊天系统。
- 先从导航和主流程排除不需要的页面；确认无引用和数据依赖后再物理删除，避免破坏性清理。

## 必须保留（P0）
1. 聊天、会话上下文和历史记录。
2. 固定 Agent ID、身份、角色、边界和版本化人格配置。
3. 服务端强制执行的私有记忆隔离，默认不共享。
4. 监督式自主：提出计划可以自动，产生副作用的执行必须审批。
5. 任务状态：提议 → 计划 → 待批准 → 执行 → 完成/失败/拒绝。
6. 关键操作审计、错误处理、备份与恢复。
7. 最小权限、输入校验、速率限制；服务端密钥不得放进前端。

## 加分项（P1）
- 从任务结果提炼经验，经过验证后写入长期记忆。
- 模拟 ZHI 资源账本，不接真实资金。
- 在聊天界面展示任务简报，不另建观察台。
- 可替换模型适配层；模型输出必须先校验。
- 经明确授权的智能人协作，只交换获批结果。

## 排除或暂缓
- 智能人观察台作为主界面：不做、不放主导航、不增加功能。
- 与管理型智能人无关的亲密关系、宫廷和成人互动模块：不进入核心依赖。
- 未审计的自动循环、广播、外部工具和真实资金操作：默认关闭。
- 不重复建设聊天 UI、消息历史或身份体系。
- 不批量执行旧 migrations。

## 验收标准
- 未授权主体不能读取聊天记录或记忆；Agent A 无法读取 Agent B 的私有记忆。
- 未批准任务无法执行，重复请求不会造成重复副作用。
- 前端和 Git 历史中不出现服务端高权限密钥。
- 删除旧模块前完成引用检索、数据依赖检查、回归测试和回滚准备。

## 实施顺序
1. 核对实际 Supabase 项目、表、RLS、Edge Functions 和前端调用。
2. 以现有聊天系统为主入口，统一 agent/session/message 数据路径。
3. 补齐任务审批与审计。
4. 验证私有记忆的服务端鉴权与数据库策略。
5. 将经验反思、模拟账本和简报作为可选增强。
6. 排除不需要的导航/部署项，测试通过后再决定是否删源文件。
