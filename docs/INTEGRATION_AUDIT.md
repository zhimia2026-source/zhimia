# 现有聊天系统接入审计（静态初审）

**状态：仅对用户上传的 `ZEE-main.zip` 做静态抽样；未连接或检查线上 Supabase 项目。** 本文不是完整安全审计，也不代表线上部署与压缩包一致。

## 已确认的可复用方向

- `agent-talk.html`：优先作为现有聊天主界面，保留 UI 与用户使用习惯。
- `zhi-agent-chat-history`：现有管理员历史记录读取入口，可作为历史适配层的参考。
- `zhi-agent-chat-feed`：现有主动消息 feed，可作为消息读取适配参考。
- `zhi-agent-autonomous-chat`：可供研究模型调用、状态读取和主动消息流程；在完成安全整改前，不应直接作为标准接口的执行后端。

## 静态初审发现

1. **两个 Supabase 项目必须保持边界。** 客户端代码分别配置 Core 与 Finance 项目；不得混用两个项目的用户 JWT，也不得把 Finance 登录状态当作 Core 身份授权。
2. **服务角色密钥只能留在 Edge Function 服务端。** 不得放进浏览器、公开 Manifest、仓库或日志；前端只能使用适当的 publishable key。
3. **历史读取目前是管理员专用接口。** 其返回结果一次最多收集大量历史消息，不是面向普通成员的分页读取 API。接入标准接口时应新增服务端分页、会话范围检查和 `chat.read` 独立授权，不应直接开放原接口。
4. **主动聊天依赖内部共享密钥。** 当前函数通过数据库配置中的共享 secret 验证调度请求。接入标准协议前，应保留服务端验证、增加轮换和审计，并确认该密钥不会出现在前端或错误响应中。
5. **主动聊天存在非事务性多写入风险。** 消息、记忆和 mind 状态分别写入；其中一项失败可能导致部分记录已落库。需要幂等键、失败补偿或事务化写入策略，避免重复消息与记忆不一致。
6. **年龄判断默认值需要复核。** 抽样代码中没有出生记录的智能人会被推断为成年人。不能把“缺少年龄数据”视为“已确认成年人”；应改为默认未知/未验证并拒绝成人话题，除非有可信且符合隐私要求的验证规则。
7. **跨域策略需要收紧。** 抽样 Edge Functions 使用宽泛的 CORS 来源。CORS 不是授权机制，但上线前仍应按实际前端来源收紧，并且每个请求都做服务端认证与资源级授权。
8. **写操作需要明确的审批和审计。** 标准接口不能把“模型生成了决定”直接视为批准。涉及外部发送、写入、删除、资金或其他副作用的操作，必须按能力检查并按策略要求人工审批。
