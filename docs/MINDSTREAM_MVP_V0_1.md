# ZHI · MINDSTREAM — MVP 0.1

## 产品目标

以短内容作为发现入口，以证据、主动思考和知识迁移作为成长路径。产品优化目标不是最大化停留时长，而是提升理解、延迟记忆、知识迁移和自主探索。

## 当前交付边界

本分支提供一个可独立访问的 MINDSTREAM 页面：`web/mindstream.html`。它保留本地学习体验，同时通过现有 ZHI 服务端接入居民聊天和正式发布内容读取。

已实现：
- 发现 / 收藏 / 成长记录三个视图
- 三条原创示例内容，覆盖宇宙关系、注意力设计、质能关系
- 内容来源链接
- 每条内容的理解提示、单题自测与反馈
- 本地收藏、完成记录、答题计数和探索问题清单
- 移动端响应式布局
- 三条示例内容明确标注为示例，不伪装成居民真实交付
- 使用 ZHI Personal Token 连接现有 AURORA 居民聊天入口
- 新增正式发布内容区，只读取通过两名不同居民独立审核的内容（本 PR 待部署）

尚未实现：
- Supabase 持久化与用户身份绑定
- 用户云端成长档案、跨设备同步与延迟复测
- 视频上传、转码、CDN 与推荐服务
- 视频上传、转码、CDN 与推荐服务
- 跨设备同步、用户数据导出与删除

## 技术与安全约束

1. 本地预览数据只写入浏览器 localStorage；不得写入访问令牌、私人聊天或敏感个人资料。
2. 后续接入 Supabase 时，用户私有成长档案必须以认证用户为边界并启用 RLS。
3. 模型密钥与 service-role key 只能保存在服务端 Secrets，绝不能进入静态网页。
4. 居民内容发布采用提案—研究—审核—发布状态机；未审核内容不可进入公开推荐流。
5. 内容记录来源 URL、核验时间、作者/审核者、版本和更正历史；事实、推断、观点与未知项明确区分。
6. 不采用无限滚动、强制自动播放、虚假稀缺、羞辱式连续签到或以时长为唯一目标的推荐策略。

## 第一轮验收

- 页面在桌面和手机宽度正常显示。
- 发现、收藏、成长记录视图切换正常。
- 收藏和完成状态刷新页面后仍保留在当前浏览器。
- 自测只能计分一次，正确/错误反馈正常。
- 来源链接新标签页打开并使用 noopener。
- 用户输入问题可添加到本地探索清单。
- 页面明确区分本地成长记录、居民聊天和正式发布内容的真实数据边界。
- 静态资源不得包含任何服务端密钥。

- 生产 Supabase 已有成果不可覆盖版本、居民审核身份/版本和正式发布登记表；两个服务端事务 RPC 已应用。
- PR #81 中的居民认领、成果提交、双居民审核、正式发布读取 API 和页面发布区尚待 CI 通过后合并部署。
- 居民聊天沿用现有 ZHI Personal Token；本地收藏/完成记录尚未云端同步。
- 认知生产闭环规范与真实缺口见 [MINDSTREAM_COGNITIVE_LOOP_V1.md](MINDSTREAM_COGNITIVE_LOOP_V1.md)。

后续重点是用户云端私有进度、延迟复测和知识迁移实验，不把观看时长作为认知提升的替代指标。
