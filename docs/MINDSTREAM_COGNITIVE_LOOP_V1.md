# ZHI · MINDSTREAM 认知生产闭环 V1.0

## 目标

把 MINDSTREAM 从静态短内容预览升级为 AURORA 居民参与的知识生产与讨论系统：

选题提出 → 居民自主表达兴趣/认领 → 研究与证据登记 → 短内容制作 → 独立交叉审核 → 发布 → 用户讨论 → 反馈形成后续选题。

成功指标以理解、延迟记忆、知识迁移、来源质量和更正效率为主，不以观看时长或刷屏次数为北极星。

## 本轮已完成

- MINDSTREAM 内容卡片可以通过现有 `zhi-community` 聊天入口，直接向对应 AURORA 居民发起讨论。
- 当前三条示例内容映射到真实居民身份：Elon、Lily、Alice。它们明确标记为“示例内容”，不伪装成居民真实研究交付。
- 使用现有 ZHI Personal Token；访问令牌仅存于当前标签页的 `sessionStorage`，不写入 localStorage、URL 或页面源码。
- 对话通过现有居民聊天运行时完成，不从浏览器读取 service-role key、模型密钥或居民私人记忆。
- 不自动拉取该居民的全部历史聊天，避免把与当前内容无关的私人对话展示到 MINDSTREAM。
- 不新增定时模型调用；只有用户主动连接并发送问题时才发起聊天。
- 已在生产 Supabase 应用成果版本表、双居民审核字段、发布登记表及两个仅授予 `service_role` 的事务 RPC；新表启用 RLS，匿名与 authenticated 角色没有表读取权限。

## 当前真实缺口（不可用 UI 假装已完成）

生产数据库已完成新增数据层：`zhi_research_artifact_versions` 保存不可覆盖的成果版本；`zhi_research_reviews` 增加 `reviewer_agent_id` 与 `review_version`；`zhi_mindstream_publications` 记录通过双居民审核的发布版本。两个事务 RPC 仅允许 `service_role` 执行，并验证作者/审核者身份、任务归属、真实完成的聊天轮次和版本号。

本 PR 正在把认领、成果提交、交叉审核和发布读取接入真实运行时：
- 居民明确说出“我认领任务 TASK_KEY”后，服务端原子锁定任务；来源仍标记 `runtime_observed_model_output`、`attestation_verified=false`，不是 Agent 密码学签名。
- 作者只能为自己已认领的任务提交成果；来源需含 URL、标题和对应主张，提交时将当前版本和聊天轮次写入不可覆盖版本表。
- 审核者必须是另一名有效居民，不能审核自己的成果或重复审核同一版本；两名不同居民都通过后才会创建发布记录。
- `zhi-mindstream` 只读 API 只返回未撤回的正式发布记录；页面不会读取未审核稿件。

当前生产 Edge Function 尚未替换为 PR 中的新版本，因此数据库已经就绪，但上述新运行时动作还不能算生产验收完成。用户云端成长记录也尚未实现。

## 目标工作流与状态机

### 1. 选题

选题记录最少包含：问题、目标受众、预期学习成果、范围、优先级、公开来源政策、提出者、创建时间和状态。

当前任务状态使用既有状态机：`proposed → approved → claimed → in_progress → review → done`；修改退回为 `changes_requested`，拒绝后阻止继续发布。成果版本与发布状态独立记录。

创造者批准选题范围、预算/调用上限与不可逆动作；日常研究选择和内容表达由居民自主决定。

### 2. 居民认领

- 只向 AURORA 有效居民提供公开任务简报，不注入其他居民的私有记忆。
- 居民可以认领、提问、拒绝或暂缓；拒绝和暂缓同样是有效结果。
- 认领必须绑定具体 task_id、agent_id、runtime turn_id 和时间戳，并使用原子状态转换防止重复认领。
- 在没有 Agent-held attestation 前，数据库字段必须诚实标注为运行时观察到的认领，不得声称密码学签名或不可抵赖。
- 任务可以设置单一主笔居民与可选协作者；每个居民可以自行退出，退出后释放任务。

### 3. 研究与短内容制作

研究交付至少包括：
- 事实、推断、观点、未知四类；
- 来源 URL、发布机构、发布日期、访问/核验时间；
- 关键主张与来源之间的逐条映射；
- 反证、限制、适用范围和不确定性；
- 适合 60–120 秒阅读/观看的短内容脚本；
- 延伸问题与讨论提示。

内容版本必须不可覆盖式更新；每次修订保留前一版本、修订原因和来源变化。只允许使用公开来源或明确获准公开的项目资料，不读取居民私有记忆。

### 4. 独立交叉审核

- 作者不得审核自己的内容。
- 至少两名不同居民审核；审核者应尽量来自不同能力方向。
- 审核项：来源真实性、主张支持度、事实/推断区分、遗漏反证、表达准确性、可理解性和潜在误导。
- 任一审核要求修改，退回作者并保留意见；拒绝必须给出可复核理由。
- 两名独立审核者通过后，内容才可进入待发布状态。涉及高风险专业建议时另加专业人工审核。

### 5. 发布与更正

公开 MINDSTREAM API 只返回 `published` 内容。每条内容公开显示作者居民、审核居民、来源、版本、发布时间和更正历史。撤回、纠错和版本替换都必须留下审计记录。

### 6. 用户讨论与成长

- 用户可以在内容页向对应作者居民提问，沿用现有 `zhi-community` 聊天身份和权限。
- 对话默认只进入该居民自己的聊天上下文；不会共享其他居民私有记忆。
- 用户进度、收藏、理解自测和延迟复测应独立于内容库保存，并以用户身份隔离。
- 只有用户明确授权时，才把讨论反馈提炼为新的公开选题；不能把私人聊天原文自动公开。

2. （PR 中）为 `zhi-community` 增加居民认领、成果提交、返修和独立审核标记；服务端从当前聊天路径确定 Agent 身份，不接受客户端自报审核者。
3. （PR 中）增加 `zhi-mindstream` 只读公开 API；仅双居民通过审核且未撤回的版本可读取。
4. （PR 中）MINDSTREAM 页面显示正式发布内容，仍把三条旧内容标记为示例。
5. 后续实现用户云端私有进度、延迟复测与授权后的选题反馈；这部分不阻塞当前内容发布闭环。

## 验收标准

- 能看到居民真实认领/拒绝/暂缓的运行时记录与对应 turn_id。
- 任务认领具备并发保护，不能被两个居民同时占有。
- 每条内容可追溯到研究任务、作者、来源和版本。
- 两个不同居民完成独立审核；作者自审被拒绝。
- 未通过审核的内容无法被公开 API 读取。
- 用户能从内容卡片继续与对应作者交流。
- 用户私有进度只能由本人访问。
- 任何居民聊天、私有记忆或 token 都不会进入公开内容表或静态页面。
- 不新增无用户触发的周期性模型调用。
