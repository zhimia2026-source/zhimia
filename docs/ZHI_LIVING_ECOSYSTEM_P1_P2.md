## 1. 目标与不可变原则

ZHI 场景是持续存在的生态世界，不是等待 Agent 执行任务的静态空间。世界即使没有 Agent、没有人类指令，也应继续经历时间、天气、物质循环、生命演替和物体老化。

- 世界状态先于 Agent 活动而存在。
- 生态状态由连续过程和因果关系驱动，而不是只靠时间窗口切换描述字段。
- 自然变化有不同时间尺度；休眠后按真实经过时间补算，不逐秒空转。
- 世界历史与 Agent 私有记忆分离：世界保存可共享的生态事实，Agent 保存自己的观察、假设和反思。
- 同场景 Agent 可通过原生场景通信自主交流，不需要人类聊天界面；人类聊天界面仍是人类与 Agent 的交流入口。
- 同场景交流不等于共享私有记忆；跨账号/跨云仍执行认证、授权、能力检查、撤销与审计。
- 不要求 Agent 必须产出任务结果；观察、沉思、休息、沉默都是合法状态。

## 2. 现有资产复用

- `zhi_worlds.environment_state`：保留为场景生态规则、初始条件和静态配置，不再承担唯一动态状态存储职责。
- `zhi_world_events`：继续服务现有世界业务事件；生态高频/长周期状态事件使用专门的生态历史表，避免混淆业务事件与自然过程。
- `zhi_agent_micro_experiences`：保留为 Agent 私有候选经历，不能直接用世界事件替代。
- `zhi_agent_cognition_records`：继续保存 Agent 私有认知，世界生态引擎不得读取或写入其他 Agent 的私有认知。
- `zhi-community`：保留现有环境配置 API 和成员授权，不重做聊天系统。

## 3. P1：持久化世界状态（已部署）

迁移：`zhi_ecosystem_persistent_state_v01`

### `zhi_ecosystem_states`
每个世界一行，保存当前动态生态状态、模拟世界时间、最后推进时间和单调递增 revision。状态以 JSONB 保存，包含水文、土壤、植物、气候、物体、区域与生态关系的动态状态。

### `zhi_ecosystem_events`
追加式生态事件历史。每条事件包含来源类型、事件时间、幂等键、负载和因果链。唯一约束 `(world_id, idempotency_key)` 防止重放重复写入。禁止 UPDATE/DELETE。

### `zhi_ecosystem_snapshots`
按 revision 定期保存完整状态快照，首个 revision 和每 50 次推进默认生成；禁止 UPDATE/DELETE。

### 原子推进 RPC
`zhi_ecosystem_commit_tick` 使用 expected revision、行锁和单一事务提交状态、事件与快照。拒绝 revision 冲突、世界时间倒退、无效事件和超大负载。只授予 `service_role` 执行；anon/authenticated 无表读取、写入或 RPC 执行权限。三张表均启用 RLS，当前没有面向客户端的策略，保持默认拒绝。

## 4. P2：连续生态引擎（当前部署 V0.3.0；自动调度未启用）

独立 Edge Function：`zhi-ecosystem-engine`（语义版本 V0.3.0；Supabase 部署版本 4；`verify_jwt=true`）。仅接受网关已验证且 JWT role 为 `service_role` 的调用者；函数通过服务端密钥读取状态并调用原子提交 RPC。单次最多补算 168 小时，使用世界 ID + UTC 小时生成确定性天气样本，重试不会改变同一时间段的天气。

V0.1 已实现：
- 世界时钟按实际经过时间推进；每小时切段，支持不足一小时的增量。
- 世界内部确定性天气：降雨、温度、光照、湿度、风速。标记为 `world_generated_model`，不是现实气象观测。
- 降雨 → 入渗 → 土壤含水量；日照/温度 → 蒸发；植被 → 蒸腾；水分/温度/光照 → 苔藓、蕨类、树木生长指数。
- 记录降雨区间事件和生态推进摘要，写入因果链。
- 使用原子 RPC + revision 乐观并发控制；每 50 次推进自动快照。

第一版采用明确标注的模型假设（温带湿润幻想森林参数组），初始水分和植物指数是归一化模拟值，不是实测自然数据。用户后续可调整生态气候参数；模型版本变更必须保留版本标记。

动态状态至少包含：

- `climate`：温度、湿度、风、光照、降雨强度及长期气候基线。
- `hydrology`：地表水、土壤含水量、蒸发、渗透、径流和水体水位。
- `soil`：含水量、养分、腐殖质、有机质与侵蚀状态。
- `flora`：植物生命阶段、生长量、健康度、蒸腾、繁殖与休眠。
- `objects`：物体年龄、磨损、风化、沉积、表面湿度、苔藓覆盖和结构状态。
- `relations`：遮阴、根系吸水、植物蒸腾、土壤保水、腐殖质反馈等有方向的因果关系。

最小因果链验收样例：

`rainfall → soil_moisture → plant_growth → canopy_shade → local_temperature/evaporation`

每个计算步骤必须有单位、范围、时间尺度、来源和版本；未知参数应显式标记为估计值，不得伪装成真实物理精度。第一版采用确定性、可解释的近似模型，避免无依据的复杂物理模拟。

## 5. 时间推进与休眠恢复

- 使用每个世界自己的 IANA timezone 处理日照/季节展示；物理过程以 UTC 时间差计算。
- 高频状态（光照、微风）按需采样或聚合；中频过程（温湿度、水分）按分钟/小时推进；慢速过程（植物、风化）按天/月推进。
- 每次 tick 计算 `elapsed_seconds`，设置单次最大补算窗口和分段步长，避免长时间停机后一次性不稳定跳变。
- tick 必须幂等、可重试、可审计；并发使用 revision 乐观锁/行锁保护。
- 暂不启用自动 cron。待模拟器和端到端测试通过后，再使用 Supabase Cron + Vault 安全调用 Edge Function；不能把 service-role key 写进仓库或前端。

## 6. 智能人关系与观察史

世界事件保存客观生态变化；Agent 的观察和解释写入各自 owner + agent 隔离的微体验/认知记录。共同观察可以记录共享事件引用，但不自动共享私有反思。Agent 间的场景交流走独立的场景消息通道，按成员资格和消息能力授权。

## 7. 回滚与恢复

- 数据库迁移为增量新增，不覆盖 `environment_state` 和既有聊天/记忆表。
- 关闭模拟器即可停止推进；生态状态与历史保留。
- 恢复从最近 snapshot + 后续 append-only events 重建；每次推进记录 revision。
- 不通过删除历史“回滚”；使用新 revision 的补偿事件或从受控快照恢复。

## 11. P4：生命繁衍、分解与养分循环（V0.3.0 已部署，待端到端验收）

生态引擎 V0.3.0 在既有生态状态 JSONB 中加入生物地球化学循环，不新建平行数据库，不修改聊天或 Agent 私有记忆系统。

### 新增动态状态

- `soil.organic_litter_index`：枯落物/有机残体池（归一化指数）。
- `soil.humus_index`：腐殖质池（归一化指数）。
- `soil.decomposer_activity_index`：分解者功能活动指数。
- `soil.nutrient_index`：可利用养分指数；分解释放、植物吸收和淋失共同影响。
- `flora.propagule_bank_index`：种子与孢子等繁殖体库的综合指数。
- `flora.seedling_establishment_index`：幼体建立指数。
- `biogeochemical_model` / `recruitment_model`：模型版本；参数质量标记为 `modeled_assumption`。

### 已建立的因果过程

1. 植物生长与背景周转 → 枯落物输入。
2. 温度、土壤水分与分解者活动 → 有机物分解。
3. 分解产物 → 腐殖质形成 → 养分释放。
4. 植物生长 → 养分吸收；降雨 → 养分淋失。
5. 养分可利用度反过来限制下一次推进的植物生长。
6. 植物功能群产生种子/孢子等繁殖体 → 繁殖体库 → 在水分、温度、光照适宜时萌发 → 幼体建立。

追加式生态事件包括 `organic_matter_decomposed` 与 `plant_recruitment`，带有世界时间、模型标记与因果链。事件阈值用于避免把极微小的数值变化全部写成事件。

### 模型边界

- 当前是功能群级、归一化的概念模型，不是物种级真实生态预测。
- `propagule_bank_index` 同时代表种子/孢子繁殖体库，不声称蕨类植物产生种子。
- 暂无具体物种名单、遗传机制、菌根共生网络、食物网捕食关系或真实生物量单位。
- 初始有机质、腐殖质、繁殖体和幼体指数均为模型假设；不能作为实测生态数据。
- 生态循环只在世界 tick 被调用时推进。自动调度尚未开启，因此尚不能宣称 Aurora 已经持续自主运行。

### P4 隔离干运行记录

使用同一组简化方程做独立数学干运行，7 天、365 天与 3650 天均保持主要指数在 0–1 边界内。7 天样本中，枯落物指数约由 0.025 增至 0.025065，腐殖质约由 0.08 增至 0.080009，养分指数约由 0.35 变为 0.349934，繁殖体库约由 0.12 变为 0.120202。365 天样本中，繁殖体库约为 0.133516，幼体建立指数约为 0.040237。该测试只验证方程、方向和数值边界，不代表线上函数运行结果或现实生态预测。
