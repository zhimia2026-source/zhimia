# ZHI 任务执行与可信回执协议 v0.1

状态：**设计契约 / 未部署**。本文定义任务从“被提出”到“被可信确认”的边界。它不代表仓库已具备真实工具执行器、跨云签名验证或生产授权服务。

## 1. 目标与硬边界

将社区任务状态机与未来的本地/跨云执行端连接起来，同时保留监督模式、最小权限和可审计性。

- 任务登记不等于执行；排队不等于执行；请求取消不等于外部副作用已停止。
- 智能人、创造者、场景 owner、托管云、执行端是不同主体。任何主体都不得仅凭角色名称获得未明确授予的权限。
- 只有服务端验证的主体身份可参与授权判断。请求体中的 actor、executor、owner 或 result 字段不能证明身份或结果真实性。
- 默认禁止访问私有记忆、跨场景读取、任意工具调用和副作用操作。每项能力必须单独授权。
- 未验证的回执不能将任务推进为 `COMPLETED`。
- 本规范不要求各方统一部署；执行端可运行在不同云或本地环境。

## 2. 主体与责任

| 主体 | 可做的事 | 不自动拥有的权限 |
|---|---|---|
| 请求智能人 | 创建任务、查询自身任务、请求取消 | 执行工具、批准自己的高风险副作用 |
| 创造者/场景 owner | 按场景策略批准任务或管理场景 | 读取智能人的私有记忆、伪造执行回执 |
| 授权服务 | 验证策略、签发短期任务授权票据、记录撤销 | 代替执行端声称执行成功 |
| 执行端 | 在票据范围内执行获准动作并提交回执 | 扩展票据权限、访问未授权数据 |
| 任务协调器 | 校验票据与回执、推进任务状态、写审计 | 跳过授权或将超时视为成功 |

## 3. 生命周期

推荐状态路径：

`CREATED → QUEUED → RUNNING → COMPLETING → COMPLETED`

异常路径：

- `CREATED/QUEUED → CANCELLED`：尚未开始或确认未产生副作用。
- `RUNNING → CANCEL_REQUESTED → CANCELLED`：只有执行端确认已停止且副作用状态已核对后，才可最终取消。
- 任意非终态 → `FAILED`：有可验证的失败结果，且没有未解决的副作用不确定性。
- 任意非终态 → `EXPIRED`：任务尚未执行且已过期；若执行可能已开始，应进入恢复流程。
- `RUNNING/COMPLETING → RECOVERY_REQUIRED`：超时、回执丢失、签名无效或副作用状态不确定。
- 任意可执行状态 → `BLOCKED`：授权撤销、策略变更或安全检查失败。

终态不可重新打开。恢复必须创建新的恢复记录或新任务，并关联原任务；不得通过覆盖历史状态抹去失败或撤销事实。

## 4. 执行授权票据

授权服务只在完成认证、逐项授权和监督审批后签发短期票据。建议采用签名 JWT/JWS 或等效的可验证签名格式；具体算法、密钥发现与轮换应由正式部署配置固定，不能在不同实现间静默降级。

票据至少包含：

- `iss`：授权发行方稳定标识；
- `aud`：唯一执行端或受信执行服务；
- `sub`：发起任务的稳定智能人身份；
- `task_id`、`scene_id`、`request_id`；
- `action_hash`：规范化 action 的摘要，防止执行端替换动作；
- `capabilities`：允许的工具/操作白名单；
- `resource_scope`：允许访问的资源与数据字段范围；
- `approval_id`：需要监督审批时的审批记录；
- `jti`：唯一票据 ID，用于防重放与撤销；
- `iat`、`nbf`、`exp`：签发、生效与到期时间；
- 可选 `max_uses` 或 `execution_nonce`：限制使用次数或绑定单次执行。

票据必须短时有效、受众绑定、动作绑定和范围受限。执行端每次执行前都要验证签名、发行方、受众、时间、任务状态、撤销状态及动作摘要。不能联系授权服务时，默认拒绝新副作用操作；只有预先定义的低风险只读能力才可有明确的离线策略。

## 5. 执行端身份与请求

执行端必须使用独立的服务身份认证，不得只凭任务 ID 或请求体中的 executor 字段取得执行权。执行请求应包含：

- 协议与 schema 版本；
- `request_id`、`task_id`、`attempt_id`；
- 授权票据及票据 ID；
- 规范化 action 或其摘要；
- 截止时间与幂等键；
- 执行端稳定身份和回调/回执关联信息。

相同幂等键与相同动作应返回同一执行记录；相同幂等键与不同动作必须返回冲突。重试不得自动重复可能产生副作用的操作。对不支持幂等的外部系统，应先查询/对账执行状态，再决定是否重试。

## 6. 可信回执

执行端提交的回执至少包含：

- `receipt_id`、`task_id`、`attempt_id`、`ticket_jti`；
- 执行端身份、动作摘要和最终结果摘要；
- `started_at`、`finished_at`；
- 结果类别：`succeeded`、`failed`、`unknown`、`cancelled`；
- 外部副作用的关联 ID（如有）；
- 失败代码/恢复提示（如适用）；
- 防重放 nonce、签名密钥 ID 与数字签名。

协调器必须验证签名、执行端身份、票据绑定、任务/尝试关联、时间范围、nonce 唯一性及结果 schema。回执只能证明签名主体提交了该声明；对于高风险或不可逆副作用，还应要求独立查询外部系统或对账证据，不得把签名本身视为业务结果绝对真实。

## 7. 状态提交与恢复

- 只有协调器可以正式提交任务状态；执行端不能直接写入数据库终态。
- `COMPLETED` 要求有效成功回执、动作摘要匹配、授权未被撤销，并满足该动作定义的结果核验要求。
- 回执缺失、网络超时或执行端失联不等于失败，也不等于成功；应进入 `RECOVERY_REQUIRED`。
- 恢复流程先按 `task_id + attempt_id + idempotency_key` 查询执行端和外部系统状态，再决定继续等待、补取回执、人工核验、补偿或标记失败。
- 取消请求发出后，协调器应禁止启动新的尝试，并向执行端发送取消信号；最终状态须依据执行端确认与副作用核验。
- 授权撤销应阻止后续执行；对已开始的任务，按风险策略停止、完成安全收尾或转入人工恢复，并保留审计记录。

## 8. 审计事件

每次关键转换至少记录：事件 ID、UTC 时间、request/task/attempt ID、已验证主体、目标资源、授权策略版本、审批 ID、状态前后值、执行端身份、票据 ID、回执摘要、拒绝原因及追踪 ID。日志不得包含 bearer token、私有记忆全文或不必要的敏感 payload。审计记录应限制修改/删除权限，并设置保留期限。

## 9. 错误语义

实现应返回稳定、可诊断的机器错误码，至少区分：

- `AUTHENTICATION_REQUIRED` / `IDENTITY_INVALID`
- `PERMISSION_DENIED` / `APPROVAL_REQUIRED`
- `TICKET_INVALID` / `TICKET_EXPIRED` / `TICKET_REVOKED`
- `ACTION_HASH_MISMATCH` / `IDEMPOTENCY_CONFLICT`
- `RECEIPT_INVALID` / `RECEIPT_REPLAYED`
- `TASK_EXPIRED` / `CANCEL_REQUESTED` / `RECOVERY_REQUIRED`

错误响应应包含 request ID；不得在错误中泄露密钥、票据原文或其他用户的资源是否存在等敏感信息。

## 10. 最小互操作验收

在宣布该协议可用前，至少由两个独立执行端/服务实现互操作测试：

1. 有效票据允许执行范围内动作；越权工具、资源、场景和动作替换均被拒绝。
2. 过期、撤销、错误受众、错误签名与重复票据被拒绝。
3. 有效回执推进到完成；错误签名、动作摘要不匹配、重复 nonce 和错误任务关联均不能完成任务。
4. 执行端超时或回执丢失进入恢复状态，而非虚报成功。
5. 重复请求不重复产生副作用；幂等键与不同动作冲突。
6. 取消与执行竞态被测试，且审计记录保留所有尝试。
7. 私有记忆、跨场景数据和工具权限不能从消息权限推导出来。
8. 授权撤销后，新的执行尝试被拒绝；在途任务按既定策略收尾或恢复。

## 11. 实施状态

当前仓库已有本地参考任务状态机与 HTTP 适配器；本文件只补充执行授权和可信回执的设计契约。当前尚未实现的能力包括：签名票据发行/验证、执行端服务身份、真实工具执行器、签名回执验证、跨云密钥发现与轮换、生产级任务租约和副作用对账。完成文档不能替代代码、测试、部署与安全审查。
