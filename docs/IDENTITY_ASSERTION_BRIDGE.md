# ZHI 跨项目个人身份断言桥接契约 v0.1

状态：**实现契约 / 尚未部署 / 尚未端到端验收**  
适用范围：个人令牌网关与现有聊天 Core 之间的服务端身份交换。  
原则：统一协议，不统一部署；认证与资源授权分离；默认拒绝；可撤销、可审计、可回滚。

## 1. 当前问题

当前个人令牌网关位于身份项目 `lvxmygrgqtmzqgailmyl`。上传的旧聊天源码显示，聊天 Core 使用另一个 Supabase 项目。不同项目的 Supabase JWT 不能被默认视为彼此有效；旧聊天管理员令牌也不是个人身份。

本契约不代表已实现任何跨项目桥接。只有完成签名密钥配置、Core 侧验证、资源归属映射和双端测试后，才可以启用。

## 2. 参与方与信任边界

- **身份签发方（Issuer）**：验证个人访问令牌，确认其未撤销、未过期，并从可信数据库取得主体。
- **聊天 Core（Audience）**：发起一次性挑战，验证身份断言，消费挑战与断言 ID，然后按 Core 自己的数据库检查 Agent、会话及资源权限。
- **浏览器**：只持有个人访问凭证和短期交互所需数据；不得持有签名私钥、服务角色密钥或 Core 私密凭证。
- **关心机制 API**：独立授权边界。聊天身份断言不自动授予 CareState 读写或执行权。

Core 必须将外部身份映射到本地授权主体。不得假设身份项目和 Core 项目的 `auth.users.id` 相同。

## 3. 推荐交换流程

1. 浏览器向 Core 的挑战端点请求挑战。Core 生成至少 256 位随机 nonce，记录其到期时间、用途、预期 issuer/audience 与未消费状态。
2. 浏览器将个人令牌和挑战 nonce 交给身份网关。个人令牌只通过 HTTPS Authorization 头传递，不放入 URL 或日志。
3. 身份网关验证个人令牌哈希对应的记录，并拒绝未知、过期或撤销令牌；主体 ID 必须来自数据库，不接受客户端提供的 `sub`、`user_id`、角色或 scope。
4. 身份网关签发短时身份断言。断言必须绑定 Core 提供的 nonce，且不得超过 2 分钟有效期。
5. 浏览器把断言交给 Core。Core 使用仅信任的签发方公钥验证签名、算法白名单、issuer、audience、iat、exp、nonce、subject 和允许的 scope。
6. Core 在数据库事务中原子消费 nonce 并登记唯一的 `jti`。已消费挑战或重复 `jti` 一律拒绝。断言验证通过只建立可信主体上下文，不代表目标资源已获授权。
7. Core 根据服务端身份映射和授权记录，检查目标 Agent/会话归属、成员资格、能力和资源范围后，才执行具体操作。
8. 对话、历史、私有记忆、关心机制、广播和工具执行分别授权；撤销个人令牌后，身份网关不得继续签发新断言。已有断言的最长存活时间受上述 2 分钟上限约束，并由 Core 的撤销策略进一步限制。

## 4. 身份断言字段

使用签名 JWT，固定允许的签名算法，不接受 `none` 或由令牌头动态选择算法。推荐采用非对称签名：私钥只在身份签发方服务端；Core 只配置可信公钥。

必需 claims：

| 字段 | 约束 |
| --- | --- |
| `iss` | 精确匹配配置的身份签发方标识 |
| `aud` | 精确匹配唯一聊天 Core 服务标识 |
| `sub` | 已验证的身份项目主体 UUID |
| `iat` / `exp` | 签发和过期时间；有效期不超过 120 秒 |
| `jti` | 使用密码学安全随机数生成的唯一 ID |
| `nonce` | 与 Core 未消费挑战完全一致 |
| `scope` | 仅包含本次所需的最小能力，不允许客户端扩大 |
| `v` | 断言契约版本，例如 `zhi-identity-assertion/0.1` |

建议初期只允许 `chat.bootstrap` 这一交换能力。聊天读取、发送、记忆访问、CareState 读写、广播和工具执行不能由 bootstrap scope 推导获得。

不得在断言中包含完整消息、健康数据、私有记忆、原始个人令牌或 refresh token。

## 5. Core 资源授权规则

断言验证之后，Core 仍必须逐请求验证：

- 身份映射处于有效状态，且未被撤销；
- 目标 Agent 属于当前主体，或存在明确的交互授权；
- 会话成员关系有效，读取历史时按会话和主体双重过滤；
- 公开目录仅返回公开名片，不返回私有状态、记忆或内部数据；
- 请求能力已被明确授予，且目标资源在授权范围内；
- 分页、消息体大小、速率限制和幂等规则有效。

客户端提交的 `user_id`、`agent_id`、`conversation_id`、`scope` 或 `role` 都是不可信输入。它们只能作为待检查的资源选择参数，不能成为授权依据。

## 6. 数据与密钥要求

- 身份项目只存个人令牌哈希；不在日志中记录原始令牌。
- 私钥只存于身份项目的服务端 secret 管理中；不得写入 GitHub、浏览器代码或前端环境变量。
- Core 只保存可信公钥与 issuer/audience 配置；不得保存身份签名私钥。
- Core 挑战记录须包含 nonce 哈希、预期用途、过期时间、消费时间，并对 nonce 设置唯一约束。
- 断言消费表对 `jti` 设置唯一约束；nonce 消费与 jti 登记应在同一数据库事务中完成。
- 断言、nonce、挑战 ID 不应写入一般业务日志；日志只记录不含秘密的结果码和关联 ID。
- 两端都必须有密钥轮换流程：新旧公钥可短暂重叠，轮换完成后移除旧公钥。
- 如果服务端密钥、目标 issuer/audience 或身份映射未配置，必须 fail closed，不能降级为管理员共享 token。

## 7. 错误语义

- `401 invalid_identity_credential`：个人凭证无效、过期或已撤销。
- `400 invalid_challenge`：挑战格式或用途无效。
- `401 invalid_assertion`：签名、issuer、audience、时间或 claim 校验失败。
- `409 challenge_replayed`：挑战已消费或断言 `jti` 重复。
- `403 resource_scope_denied`：身份已验证，但目标资源/能力未授权。
- `503 identity_bridge_unconfigured`：服务端密钥或必要配置缺失。

错误响应不得泄露其他主体是否存在、是否拥有某个 Agent，或任何签名材料。

## 8. 必须通过的测试

- 缺少令牌、伪造令牌、未知令牌、过期令牌和撤销令牌均被拒绝。
- 客户端伪造 `sub`、`user_id`、`scope`、`iss`、`aud` 不会扩大权限。
- 错误签名、错误 issuer/audience、过期断言、未来签发时间和错误 nonce 均被拒绝。
- 同一个 nonce 或 `jti` 的并发重放仅允许一次成功消费。
- 主体 A 不能读取主体 B 的 Agent、会话、历史、私有记忆或 CareState。
- 身份映射被撤销后，新请求被拒绝；旧断言在约定时限内失效。
- 聊天 bootstrap 断言不能调用 CareState 写入、广播或工具执行。
- 日志、错误响应和前端存储中没有原始令牌、私钥或私有消息内容。
- 原聊天入口在切换前完成桌面/移动端回归；失败时可回滚到旧版本，但不得重新开放不受控的共享管理员访问作为长期方案。

## 9. 分阶段发布与回滚

**阶段 A：只读准备** — 部署挑战与验证端点，但不改变现有聊天入口；用测试身份验证签名、过期、重放和授权失败。

**阶段 B：影子验证** — 对测试请求同时运行旧路径与新路径的只读授权判断，不执行写入；比较结果并检查日志。

**阶段 C：有限启用** — 仅对明确选择的测试账号开放聊天发送与历史读取；开启跨账号隔离和撤销测试。

**阶段 D：正式切换** — 只有阶段 A–C 的验收证据齐全后才逐步切换。保留版本化回滚点；不要在验证前删除旧代码或改变生产入口。

任一阶段若签名验证、nonce 消费、身份映射、RLS 或隔离测试失败，应停止发布并回滚应用版本。不得通过关闭 JWT 验证、信任客户端主体字段或重用管理员令牌绕过失败。
