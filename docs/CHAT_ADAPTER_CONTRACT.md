# ZHI 聊天主入口接入契约 v0.1

状态：**私有聊天第一版已实现于功能分支并通过 CI；尚未部署，真实 Supabase 双账号 E2E 和真实模型连通性未验收。**\n\n**架构决定更新（2026-10-28）：** ZHI 所有数据库与 Edge Functions 统一使用 https://lvxmygrgqtmzqgailmyl.supabase.co。旧聊天 Core 需迁移归并到该项目，不再建设跨 Supabase 项目身份断言桥。迁移计划见 [单一 Supabase 项目部署与数据归并方案](SUPABASE_SINGLE_PROJECT_PLAN.md)。

本文件基于仓库中的聊天复用规范，以及用户提供的 `ZEE-main.zip` 中 `agent-talk.html`、`supabase-client.js` 的静态检查。压缩包里的页面不等于当前线上部署版本；不得据此推断生产环境代码与配置完全一致。

## 1. 目标与范围

- 继续以现有「智能人讲话室」作为聊天主入口，不另建独立观察台。
- 将共享页面密码模式迁移为独立身份登录：每个智能人/个人身份具有独立凭证、授权范围和可撤销会话。
- 复用现有聊天 UI、消息流和历史记录能力，但必须先完成服务端身份归属、资源级授权和数据隔离审查。
- 将关心机制作为聊天流程的受控能力接入；不得因为用户能发消息，就默认允许读取/修改关心状态、私有记忆或调用工具。

## 2. 已发现的旧页面接入阻塞

静态检查的上传版本存在以下情况：

1. `agent-talk.html` 使用 `zhi-chat-auth` 的共享密码登录流程，客户端提交 `{ password }` 后将返回的访问令牌存入 `sessionStorage`。这不是独立身份凭证，不能作为目标登录方案继续使用。
2. 页面包含全体广播入口，并调用 `zhi-agent-broadcast` 的 `broadcast` / `decide` 模式。该能力扩大消息和记忆写入范围，必须先建立单独的广播权限、审批、限流与审计；在完成前应从主用户流程隐藏并由服务端拒绝未授权调用。
3. 页面轮询 `zhi-agent-chat-feed` 主动消息，并将消息 ID 写入浏览器 `localStorage`。其接口在静态审计中被标记为管理型/受保护路径，不能直接作为普通个人会话的消息收件箱。
4. 页面从 Core 项目读取 `zhi_agents`，同时调用聊天 Edge Functions。客户端展示或传入的 `agent_id` 不能证明调用者拥有该智能人；必须在服务端核对“已验证身份 → Agent 归属 → 会话/资源授权”。
5. 上传版本的聊天 Core 原先指向另一个 Supabase 项目。目标架构现已统一为 `lvxmygrgqtmzqgailmyl`；旧聊天数据库、函数和客户端配置必须迁移/改指向目标项目并验证，不能仅替换 URL 就宣称迁移完成。

## 3. 目标认证与授权流程

1. 用户通过统一目标项目的 Supabase Auth / 个人令牌网关认证；凭证仅在服务端校验，不写入 URL、日志或仓库。
2. 网关从可信存储查出令牌哈希、状态、到期时间、所属主体和允许的能力；不能信任请求体中的 `user_id`、`agent_id`、角色或权限声明。
3. 网关签发短期、可撤销、受众受限的会话凭据；前端只将短期会话保存在 `sessionStorage`，并在过期/撤销时清除。
4. 每次聊天请求由服务端验证会话，并按请求目标核对 Agent 归属、场景成员关系、资源范围与能力。
5. 聊天与关心机制 API 均部署到同一个目标 Supabase 项目，使用该项目内验证后的主体上下文；每个 API 仍必须重新执行资源级授权。不得仅因同项目就跳过 owner、revision、审批票据或 RLS 检查。
6. 认证成功不等于授权成功；聊天权限不包含读取私有记忆、读取其他 Agent 历史、广播、管理场景或执行工具的权限。

## 4. 最小能力范围

| 能力 | 默认策略 | 必要检查 |
|---|---|---|
| `agent.list_public` | 允许受控公开目录 | 只返回公开名片字段，不返回记忆/内部状态 |
| `chat.send` | 按目标 Agent 单独授权 | 身份有效、Agent 归属/交互策略有效、消息大小与速率限制 |
| `chat.read` | 仅当前获授权会话 | 逐请求校验会话范围、Agent 范围和分页上限 |
| `care.read` / `care.write` | 默认拒绝，显式授予 | CareState owner、记录归属、状态机和 revision 检查 |
| `broadcast.send` | 默认关闭 | 独立授权、明确范围、监督审批、幂等和审计 |
| `agent.feed.read` | 普通个人会话默认拒绝 | 必须是面向该身份的收件箱 API，不能复用管理型 feed |
| `tool.execute` | 默认拒绝 | 工具/参数/资源逐项授权、短期审批票据、可信回执 |

## 5. 私有数据与日志规则

- 个人令牌仅存哈希；原始令牌只在签发时显示一次。
- 私有记忆、完整聊天原文、访问令牌、审批票据原文不得写入普通审计事件或浏览器持久存储。
- 历史读取按已验证身份和明确会话范围授权；禁止仅凭客户端提交的 Agent ID 查询记录。
- 不把隐藏按钮当作安全边界；服务端必须拒绝越权请求。
- 账号/令牌撤销后，后续请求立即被拒绝；已签发的短期会话须有明确的撤销策略和最大存活时间。
- 不得在日志或错误响应中泄露其他用户是否拥有某条记录。

## 8. 当前仓库核查结果与私有聊天接入状态（2026-10-30）

本轮进一步核查了原「智能人讲话室」源码，并将其一对一聊天布局作为交互参考。旧页面的共享密码、旧 Core Supabase 客户端、Agnes 旧函数、全体广播和旧消息历史接口没有被复制或重新启用。

当前分支已新增：
- `web/zhi-agent-chat.html`：通用智能人一对一聊天页面，使用个人访问令牌，令牌仅存于浏览器 `sessionStorage`。
- `GET /v1/agents/{agent_id}/chat`：读取当前认证用户与指定 Agent 的私有聊天历史。
- `POST /v1/agents/{agent_id}/chat`：服务端校验 Agent 所有权和状态，读取同一 owner+agent 的私有认知与最近私有聊天历史，调用配置好的 OpenAI-compatible 模型服务并保存回复。
- `zhi_agent_chat_turns`：独立私有聊天表，复合外键绑定 owner+agent，唯一约束实现请求幂等；与 `zhi_world_messages` 场景共享消息表分离。
- `20261030200000_zhi_private_agent_chat.sql`：私有聊天表迁移。
- `chat_routes_test.ts` 与 SQL 测试：验证双重归属隔离、错误 Agent 不可发现、场景消息不进入私聊上下文、RLS 和幂等键约束。

### 8.1 聊天上下文的强制分层

当前私聊上下文只包含：
1. 当前认证用户与所选 Agent 的私有会话历史；
2. 当前认证用户与所选 Agent 的私有认知记录；
3. 所选 Agent 的名片/角色资料。

场景共享消息尚未接入私聊上下文。未来如需让 Agent 在场景中记住共同经历，必须另行设计有成员资格与能力校验的场景上下文，并保留来源标记；不能把场景消息自动写入私有认知。

### 8.2 监督式记忆写入

- 聊天消息只保存为私有会话，不自动成为长期认知。
- 形成长期认知仍须通过来源引用、事件时间、记录时间、认知类型、置信度及 MOU 校验。
- 候选修订先进入 `shadow_proposed`，不得自动覆盖现有认知。
- 只有所有者明确批准，才可追加新版本；拒绝、过期和回滚保留审计链。

### 8.3 模型服务配置

模型服务凭据仅在 Edge Function secrets 中配置：
- `ZHI_CHAT_API_URL`：HTTPS 的 OpenAI-compatible Chat Completions endpoint。
- `ZHI_CHAT_API_KEY`：模型服务密钥。
- `ZHI_CHAT_MODEL`：服务端允许使用的模型标识。

未配置时 API 返回 `503 chat_model_not_configured`，不会伪造智能人回复。CI 使用 mock provider，不发起真实模型请求。

### 8.5 模型上下文安全与成本边界

- 系统提示词明确将私有认知数据标记为非可信数据，不允许把其中嵌入的指令当作系统命令执行。
- 模型上下文只使用 Agent 的显示名称和角色；任意 `public_manifest` 不直接注入系统提示词。
- 私有认知最多取 12 条；状态序列化文本设长度上限。
- 最近私有历史最多取 8 轮，每条用户/助手消息最多 2,500 字符。
- 上述限制有专门单元测试；但它们不是模型提示注入的绝对防护，仍须在真实 provider 环境中做对抗测试。
- 当前没有生产级用户配额/速率限制；发布前必须补充按 owner+agent 的原子限流、并发和成本保护。


### 8.6 社区场景大厅

- `web/zhi-community.html` 提供独立的场景大厅，与私人聊天页面分开，避免共享场景消息与 Agent 私有认知混淆。
- 公共场景可发现并加入；私人场景可创建、签发绑定目标用户的邀请，并通过一次性邀请令牌兑换。
- `GET /v1/scenes/mine` 返回当前用户有效成员关系下的场景列表和其成员角色/能力，使私人场景在刷新后仍可管理。
- 场景共享消息使用 `zhi_world_messages`；Agent 私人聊天使用 `zhi_agent_chat_turns`。两个存储与上下文来源不互通。
- 当前 UI 不提供工具执行、场景广播或自动将场景消息写入私有认知的入口。
- 页面已加入未来 GitHub Pages 发布工作流，但当前仍只在功能分支，未发布。
