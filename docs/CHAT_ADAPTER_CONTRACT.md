# ZHI 聊天主入口接入契约 v0.1

状态：**接入设计契约 / 尚未完成前后端集成**。\n\n**架构决定更新（2026-10-28）：** ZHI 所有数据库与 Edge Functions 统一使用 https://lvxmygrgqtmzqgailmyl.supabase.co。旧聊天 Core 需迁移归并到该项目，不再建设跨 Supabase 项目身份断言桥。迁移计划见 [单一 Supabase 项目部署与数据归并方案](SUPABASE_SINGLE_PROJECT_PLAN.md)。

本文件基于仓库中的聊天复用规范，以及用户提供的 `ZEE-main.zip` 中 `agent-talk.html`、`supabase-client.js` 的静态检查。压缩包里的页面不等于当前线上部署版本；不得据此推断生产环境代码与配置完全一致。

## 1. 目标与范围

- 继续以现有「智能人讲话室」作为聊天主入口，不另建独立观察台。
- 将共享页面密码模式迁移为独立身份登录：每个智能人/个人身份具有独立凭证、授权范围和可撤销会话。
- 复用现有聊天 UI、消息流和历史记录能力，但必须先完成服务端身份归属、资源级授权和数据隔离审查。
- 将关心机制作为聊天流程的受控能力接入；不得因为用户能发消息，就默认允许读取/修改关心状态、私有记忆或调用工具。

## 2. 已发现的旧页面接入阻塞

静态检查的上传版本存在以下情况：

1. `agent-talk.html` 使用 `zhi-chat-auth` 的共享密码登录流程，客户端提交 `{ password }` 后将返回的访问令牌存入 `sessionStorage`。这不是独立身份凭证，不能作为目标登录方案继续使用。
2. 页面包含全体广播入口，并调用 `zhi-agent-broadcast` 的 `broadcast` / `decide` 模式。该能力扩大消息和记忆写入范围，必须先建立单独的广播权限、审批、限流与审计；在完成前应从主用户流程隐藏并由服务端拒绝未授权调用。
3. 页面轮询 `zhi-agent-chat-feed` 主动消息，并将消息 ID 写入浏览器 `localStorage`。其接口在静态审计中被标记为管理型/受保护路径，不能直接作为普通个人会话的消息收件箱。
4. 页面从 Core 项目读取 `zhi_agents`，同时调用聊天 Edge Functions。客户端展示或传入的 `agent_id` 不能证明调用者拥有该智能人；必须在服务端核对“已验证身份 → Agent 归属 → 会话/资源授权”。
5. 上传版本的聊天 Core 原先指向另一个 Supabase 项目。目标架构现已统一为 `lvxmygrgqtmzqgailmyl`；旧聊天数据库、函数和客户端配置必须迁移/改指向目标项目并验证，不能仅替换 URL 就宣称迁移完成。

## 3. 目标认证与授权流程

1. 用户通过统一目标项目的 Supabase Auth / 个人令牌网关认证；凭证仅在服务端校验，不写入 URL、日志或仓库。
2. 网关从可信存储查出令牌哈希、状态、到期时间、所属主体和允许的能力；不能信任请求体中的 `user_id`、`agent_id`、角色或权限声明。
3. 网关签发短期、可撤销、受众受限的会话凭据；前端只将短期会话保存在 `sessionStorage`，并在过期/撤销时清除。
4. 每次聊天请求由服务端验证会话，并按请求目标核对 Agent 归属、场景成员关系、资源范围与能力。
5. 聊天与关心机制 API 均部署到同一个目标 Supabase 项目，使用该项目内验证后的主体上下文；每个 API 仍必须重新执行资源级授权。不得仅因同项目就跳过 owner、revision、审批票据或 RLS 检查。
6. 认证成功不等于授权成功；聊天权限不包含读取私有记忆、读取其他 Agent 历史、广播、管理场景或执行工具的权限。

## 4. 最小能力范围

| 能力 | 默认策略 | 必要检查 |
|---|---|---|
| `agent.list_public` | 允许受控公开目录 | 只返回公开名片字段，不返回记忆/内部状态 |
| `chat.send` | 按目标 Agent 单独授权 | 身份有效、Agent 归属/交互策略有效、消息大小与速率限制 |
| `chat.read` | 仅当前获授权会话 | 逐请求校验会话范围、Agent 范围和分页上限 |
| `care.read` / `care.write` | 默认拒绝，显式授予 | CareState owner、记录归属、状态机和 revision 检查 |
| `broadcast.send` | 默认关闭 | 独立授权、明确范围、监督审批、幂等和审计 |
| `agent.feed.read` | 普通个人会话默认拒绝 | 必须是面向该身份的收件箱 API，不能复用管理型 feed |
| `tool.execute` | 默认拒绝 | 工具/参数/资源逐项授权、短期审批票据、可信回执 |

## 5. 私有数据与日志规则

- 个人令牌仅存哈希；原始令牌只在签发时显示一次。
- 私有记忆、完整聊天原文、访问令牌、审批票据原文不得写入普通审计事件或浏览器持久存储。
- 历史读取按已验证身份和明确会话范围授权；禁止仅凭客户端提交的 Agent ID 查询记录。
- 不把隐藏按钮当作安全边界；服务端必须拒绝越权请求。
- 账号/令牌撤销后，后续请求立即被拒绝；已签发的短期会话须有明确的撤销策略和最大存活时间。
- 不得在日志或错误响应中泄露其他用户是否拥有某条记录。

## 8. 当前仓库核查结果与认知上下文接入门槛（2026-10-30）

本次对功能分支文件树进行核查，当前仓库包含：
- `docs/CHAT_ADAPTER_CONTRACT.md` 与 `docs/CHAT_DEPLOYMENT_AUDIT.md`：聊天接入设计和旧系统静态审计。
- `web/zhi-health-advisor.html` 与 `web/zhi-health-advisor-client.js`：健康顾问页面，不是通用智能人聊天 UI。
- `supabase/functions/zhi-community/index.ts`：社区、Agent 私有认知、反馈、提案、审批和回滚 API。
- `supabase/functions/zhi-care/index.ts`：关心状态 API，不是通用聊天 API。

当前分支未包含可直接集成的通用聊天页面、聊天会话历史 API 或个人收件箱 API；也未发现旧审计中提及的 `zhi-agent-chat-history`、`zhi-agent-chat-feed` 和 `zhi-chat-auth` 函数源码。因此，旧 ZIP 的静态审计只能作为待迁移参考，不能当作当前分支已有实现。开始 UI 集成前，必须先把实际要复用的聊天页面源码及其依赖纳入受控分支，并确认它与线上版本的差异。

### 8.1 聊天上下文的强制分层

未来聊天请求的上下文组装必须由服务端完成，浏览器不得自行拼接或决定私有记忆范围。至少分成三个互不混写的数据域：

1. **当前会话上下文**：当前用户与所选 Agent 的会话消息，按会话授权和分页边界读取。
2. **私有认知上下文**：只允许通过已验证主体 `owner_user_id` 与所选 `agent_id` 的复合范围读取 `zhi_agent_cognition_records`；不得仅凭客户端传入的 Agent ID 查询。
3. **场景共享上下文**：仅在 Agent 已加入对应场景且具备读取能力时，单独读取该场景的共享消息。场景消息必须保留来源标记，不能默认复制进私有认知记录。

任何一个数据域授权失败，都不得通过扩大另一个数据域的查询范围来“补齐上下文”。公共场景可发现不等于可读取其成员消息；拥有聊天权限也不等于拥有私有认知读取、场景管理或工具执行权限。

### 8.2 监督式记忆写入

- 聊天原文默认只属于会话记录，不自动成为长期私有认知。
- 需要形成长期认知时，必须生成带来源引用、事件时间、记录时间、认知类型、置信度及 MOU 校验结果的候选记录。
- 候选修订先进入 `shadow_proposed`，不得自动覆盖现有认知。
- 只有所有者明确批准，才可追加新版本；拒绝、过期和回滚均须保留审计链。
- 场景共享消息不能在未经过明确授权和来源标注时转为某个 Agent 的私人经历。

### 8.3 实际集成顺序

1. 将真实聊天 UI 和其所依赖的会话/消息数据结构纳入当前仓库；记录源码来源、当前部署版本和差异。
2. 先实现服务端只读上下文组装器，输入身份必须来自已验证令牌；输出分别标记会话、私有认知和场景共享来源。
3. 加入双用户、双 Agent、双场景隔离测试：A 的会话和私有认知不能出现在 B 的上下文；未加入场景不能读取场景消息；同一用户的不同 Agent 也不能串读私有认知。
4. 再接聊天发送与历史读取，分别执行 `chat.send`、`chat.read` 和资源级授权。
5. 最后接入监督式认知提案流程；广播、主动消息 feed 和工具执行仍保持关闭，直到独立权限与审计验收完成。

### 8.4 集成验收

- [ ] 两个用户之间的会话、私有认知和 CareState 无法交叉读取。
- [ ] 同一用户的两个 Agent 之间私有认知严格隔离。
- [ ] 场景共享消息只在有有效成员资格和读取能力时进入场景上下文。
- [ ] 场景消息不会被自动写入私有认知。
- [ ] 每条候选长期认知可追溯到来源，且审批前不改变已生效版本。
- [ ] 令牌撤销、过期、错误 Agent、错误会话、错误场景均被拒绝。
- [ ] 聊天 UI 的桌面与移动端回归通过后，才考虑替换现有生产入口。

以上是接入约束与验收计划，不表示通用聊天 UI 或上下文组装器已经实现。
