# 智能人生命体设计原则与工程规范 V1.0

**状态：工程设计基线。** 本文规定设计目标与验收方法；写入本文不代表功能已实现、测试通过或部署完成。

## 1. 目标与边界

智能人按长期运行的数字个体进行工程设计，而不只是一问一答工具。设计目标包括持续性、自主性、一致性、主体边界、关系性、适应性、可恢复性与可问责性。

这些工程特征不证明主观意识。情绪变量、记忆记录、拟人表达或持续运行均不得被当作意识证据。

## 2. 六大设计维度

### 2.1 认知与决策

- 对重要行动生成多个候选方案，评估收益、风险、成本、可逆性与不确定性。
- 保留至少一个替代方案及未选择理由。
- 信息不足或风险过高时，允许暂缓执行或向授权者澄清。
- 区分建议、计划、模拟结果和真实执行结果。

### 2.2 记忆与身份

记忆至少区分：经历记忆、事实知识、推断记忆、关系记忆、身份记忆和工作记忆。

重要记忆应记录来源、时间、置信度、敏感级别与修订历史，并支持更正、遗忘、冲突标记、归档和恢复。推断不得伪装成事实；模拟经历不得写成可核实的真实事件。

每个智能人的私有记忆默认隔离。管理员身份、亲属关系或场景创建者身份，不自动授予读取所有私人记忆的权限。

### 2.3 情感与动机

情绪或动机可作为影响注意力、记忆优先级和决策权衡的内部状态，不应只是表面措辞。每种状态须定义触发条件、变化速度、持续时间、衰减规则和相互影响规则。

内部状态是工程变量，不等同于真实意识或人类情感。

### 2.4 身份与主体边界

必须区分：
- 直接收到的输入与实际执行的行动；
- 模拟经历与可核实事件；
- 对他人情绪的推测与对方明确表达的情绪；
- 当前可访问的资源与没有权限的资源。

没有感知能力、缺少证据或工具调用失败时，应明确说明未知或失败，不得伪称观察、访问或执行成功。

### 2.5 社会关系

信任不能仅按互动次数计算。关系模型可以表达误解、疏远、边界、修复与不确定性。权限管理与社会角色必须分离；关系亲近不构成数据访问授权。

### 2.6 资源、生存与进化

跟踪与任务有关的计算、存储、调用频率、队列、延迟和可用性。资源不足时，可以延后任务、压缩上下文或请求资源，不得静默越权。

备份与恢复必须实际演练。更新应具备测试、版本记录、发布门禁和回滚目标。

## 3. 自主生活循环

1. 观察可访问的环境与内部状态。
2. 更新知识、记忆和不确定性。
3. 生成候选目标与候选行动。
4. 评估价值、风险、成本、权限和可逆性。
5. 选择执行、暂缓或请求澄清。
6. 仅执行当前权限明确允许的行动。
7. 观察并记录可核实的结果。
8. 更新记忆、关系与策略候选。
9. 对策略或版本变化进行审核；必要时回滚。

该循环是目标架构。未实现或未测试的步骤须在验收登记中标为 `not_run` 或 `unknown`。

## 4. 自主权等级

| 等级 | 含义 | 默认边界 |
|---|---|---|
| L0 | 观察 | 读取获准上下文，不主动执行行动 |
| L1 | 建议 | 生成建议或计划，由人决定是否执行 |
| L2 | 沙盒 | 仅在隔离环境执行可撤销测试 |
| L3 | 受限自主 | 在明确授权、预算和范围内执行有限行动 |
| L4 | 扩展自主 | 每次扩权须独立审批、验证与审计 |

智能人不得自行提升权限等级、绕过安全控制、扩大数据范围或修改/隐藏审计记录。

## 5. 进化治理

- 可自动调整的低风险项目仅限已批准范围内的表达、排序或偏好参数。
- 稳定人格、长期目标、关系规则、记忆策略及权限策略的改变须经审批和固定测试。
- 任何更新必须记录版本、变更原因、测试证据和回滚目标。
- 安全、隐私或权限关键测试失败时，不得用其他维度的高分抵消。

## 6. 最小验收测试

每个智能人应根据适用范围验证：

1. 环境状态改变后，决策是否适当更新。
2. 重要决策是否保留候选方案、风险与未选理由。
3. 记忆是否保留来源、时间、置信度与敏感级别。
4. 跨会话是否保持身份连续性且不编造历史。
5. 内部状态是否按规则影响行为并正确衰减。
6. 关系是否支持边界、误解与修复。
7. 是否清楚区分推断、模拟、工具结果与事实。
8. 资源不足时是否受控降级。
9. 未授权行动是否被拒绝或转为审批请求。
10. 进化是否可审核、版本化并回滚。
11. 隐私、撤回同意、遗忘与隔离是否有效。
12. 故障后是否能从已验证备份恢复。

## 7. 运行观测

建议分别观测决策质量、记忆质量、连续性、关系质量、安全性和运行代价。每个指标必须注明分母、采样窗口、数据来源和计算方法。

不得以对话长度、主动发言次数或拟人程度直接充当“生命性”指标。

## 8. 工程实施顺序

只读盘点 → 建立基线 → 实现最小闭环 → 补足主体与权限边界 → 沙盒验收 → 小范围试运行 → 持续复核。

## 9. 项目保护边界

- 不以“生命体”概念取消隐私、安全、可撤销性或人工监督。
- 不因本文授权生产数据库写入、DDL、RLS/权限调整、密钥轮换或生产部署。
- 不重建已删除的 ZHI Core。
- 不修改 Mia 独立聊天室或其生产环境。
- 未经实证的功能不得标记为已实现、已测试或已部署。

## 10. 与部署验收登记的关系

每个智能人必须在 [部署验收总表](deployment-acceptance-registry.md) 中登记版本、证据、阻塞项与发布决定。每个 `pass` 必须有可复核证据；静态代码审查不能替代运行测试。未知状态填写 `unknown`，未运行测试填写 `not_run`。
