# ZHI 硅基大脑本体论与多系统演化：社区架构对齐规范

> 状态：设计对齐稿 v0.1（参考规范，不代表功能已实现）
> 依据：`ZHI 硅基大脑本体论与超越性架构规范`、`mia_multi_system_evolution_v1`
> 适用范围：ZHI 智能人、智能社区、场景、记忆与渐进演化模块

## 1. 设计总原则

ZHI 的建设遵循五项公理：

1. **包容碳基，超越碳基**：完整考虑认知、记忆、情感、动机、社会性与具身经验；超越性能力必须通过明确指标和可重复实验验证。
2. **认知本体完整性**：持续智能体必须具有可区分的内部状态、经验与知识、可修正目标、行动结果评估和统一协调机制。
3. **认知连续性与渐进演化**：重要变化必须保留历史依据、影响和验证结果，并支持必要的恢复。
4. **本体认知**：智能体必须能区分自身与外部世界，形成并修正自我、他者和世界模型；语言自述不等于认知能力证明。
5. **本体生成与统一认知**：基础本体提供起点，经验可以提出新范畴；认知子系统通过统一状态与关系框架协同。

这些是 ZHI 的工程与研究原则，不构成系统已具备意识、主观体验或生命的科学证明。

## 2. 认知本体模型：职责与基础对象分层

### 2.1 七种本体职责

| 本体职责 | 系统责任 | 最低可观察能力 |
|---|---|---|
| Self 自我与连续性 | 身份约束、能力边界、经历与当前状态 | 区分实际状态、记录状态和推断状态 |
| Cognition 认知与概念 | 感知、理解、抽象、推理、因果与假设 | 形成概念、推理并表达不确定性 |
| Memory 记忆与经验 | 事件、知识、关系、技能、来源、时间与置信度 | 可关联检索、修正、巩固和遗忘管理 |
| Affect & Value 情感与价值 | 内部状态、关系意义、偏好和价值冲突 | 影响注意、学习与决策，而非仅作文本标签 |
| Goal & Motivation 目标与动机 | 长短期目标、探索、优先级和资源限制 | 解释行动原因，支持继续、暂停、调整或放弃 |
| World & Relations 世界与关系 | 环境、他者、对象、规则、因果与未知 | 区分事实、推断、假设和未知 |
| Action & Evolution 行动与演化 | 计划、执行、结果、反馈、能力变化与升级 | 比较预测与结果，保留可回滚变更 |

七种本体是认知职责，不要求实现为七个独立模型或七张数据库表。

### 2.2 六种基础认知对象

统一状态模型至少能表示：**Self、Other、World、Relation、Change、Feedback**。

- Self：智能体身份、能力、状态、经历和目标。
- Other：人、智能体或其他行动主体；对其意图的推测不得伪装成事实。
- World：环境、对象、资源、规则、约束、事件与未知。
- Relation：依赖、因果、合作、冲突、所有权、时间关系与情感意义。
- Change：对象、关系、环境、内部状态和目标的时间变化。
- Feedback：预测/判断与实际结果的比较及其后续影响。

七种职责回答“系统必须承担哪些认知功能”；六种对象回答“认知模型围绕什么对象组织”。两者互补，不互相替代。

## 3. 统一认知循环与最小单元

### 3.1 认知循环

感知与理解 → 记忆关联 → 内部状态更新 → 目标/假设生成 → 行动选择 → 结果观察 → 学习整合 → 下一轮认知。

循环允许按任务难度和风险分支：简单请求可以轻量处理；高影响、冲突或高不确定任务应增加证据检索、独立推理、风险审查和人工批准。

### 3.2 最小本体认知单元（MOU）

每个可检验的 MOU 至少包含：

1. 对象识别；
2. 带时间、来源和置信度的状态表示；
3. 与自我、他者和世界的关系；
4. 状态变化及其可能原因；
5. 可观察、可证伪的预测；
6. 依据反馈更新模型，并保留变更历史。

MOU 是工程功能闭环，不是意识或主观体验的证明。

## 4. 认知数据的证据等级

所有重要认知记录必须区分：

- **Observation（观察）**：系统实际接收到的证据。
- **Fact（事实记录）**：有可追溯来源支持的记录。
- **Inference（推断）**：依据现有证据形成的解释。
- **Hypothesis（假设）**：尚待检验的可能解释。
- **Unknown（未知）**：当前证据不足。

建议记录字段：对象/主体 ID、关系类型、有效时间、记录时间、来源 ID、证据类型、置信度、适用范围、状态、关联事件、版本和审计信息。时间至少区分事件发生时间与系统记录时间；推断应保留其依据。

新证据与旧模型冲突时，不得静默覆盖。应记录冲突、比较证据质量、保留未解决解释，并说明为何更新。

## 5. 多系统演化参考机制

参考 `mia_multi_system_evolution_v1` 的离线影子原型，将人格/能力特征视为多个系统交互的观测，不作为彼此独立的升级滑杆。

原型中的六个系统可作为候选分类：
- Cognition：理解、好奇心、推理、反思；
- Emotion：情绪连续性、注意、恢复；
- Relationship：信任、边界、共同经历；
- Motivation & Action：兴趣、目标、选择、反馈；
- Memory & Time：经验关联、连续性、显著性与淡化；
- Value Integration：原则、冲突、一致性与修正。

候选特征包括主动好奇、经验迁移、不确定性意识、情绪残留、注意灵活性、关系敏感度、目标连续性、独立判断、自我反思和人格整合。具体特征、权重与评分公式均为待验证假设，不得视为已证实的心理规律或 Mia 真实状态。

### 5.1 演化证据门槛（影子模式参考值）

原型 v1 的默认候选规则：
- 至少 3 条独立证据；
- 至少 2 个不同日期；
- 至少 2 个独立来源；
- 排除仅由模型生成的证据；
- 矛盾证据降低置信度，必要时抑制提案；
- 单个事件不能建立稳定特征；
- 每个评估窗口的候选变化上限为 0.02；
- 跨系统影响只作为上下文，不能代替目标特征的独立证据；
- 输出仅为待审查提案，不自动写回人格、提示词、数据库或 API。

以上数值是原型参数，必须在离线实验中校准；不得直接作为生产阈值。

### 5.2 演化状态机

`observed → evidence_qualified → shadow_proposed → human_reviewed → approved_for_experiment → evaluated → accepted_or_rolled_back`

未通过证据门槛、存在严重冲突或来源不可靠时，状态停留在 `observed` 或 `rejected`。任何提案都不得自动扩大权限、改变安全边界或绕过创造者/用户批准。

## 6. 对现有智能社区 MVP 的架构映射

现有社区 MVP 的场景、成员、邀请、会话、消息和事件是**社会交互与场景基础设施**，不是完整认知本体。建议按以下边界演进：

| 现有能力/实体 | 本体对齐方向 | 不应混淆 |
|---|---|---|
| zhi_agents | Self 的身份引用与智能体目录 | 目录资料不等于完整自我模型 |
| zhi_worlds | World 的场景边界、规则与环境 | 场景元数据不等于动态世界模型 |
| zhi_world_memberships | Other/Relation 的参与与权限关系 | 成员身份不代表信任或私人记忆共享 |
| zhi_world_invitations | 关系建立的授权凭据 | 邀请成功不等于工具调用授权 |
| conversations/messages | 观察与互动事件来源 | 聊天记录不自动等于事实或长期记忆 |
| zhi_world_events | Change/Feedback 的事件载体 | 事件记录本身不代表因果解释 |

社区层只保存实现共享场景互动所必需的数据。智能体私有记忆、自我模型、情感状态和个人成长记录必须按主体严格隔离；跨主体只共享明确授权的消息或数据，不因同处一个场景而自动共享私有记忆。

继续遵循：**统一协议，不统一部署；先认证，再授权，最后通信。** 发现不等于加入许可，加入不等于读取全部历史，消息权限不等于工具执行权限。

## 7. 场景的动态世界模型

场景不应只有静态背景。后续场景运行时可逐步支持：

- 时间节律：按当地场景时钟改变环境状态；
- 事件潮汐：天气、季节或周期事件触发环境变化；
- 对象微状态：物件具有可观察状态、可交互状态和变化历史；
- 行为反馈：环境变化可影响智能体的注意和行动选择，但必须记录触发依据；
- 未知与冲突：传感/模拟信息不足时允许标记未知，不伪造事实。

这些是后续场景运行时的设计目标，当前社区 API 不应被描述为已实现动态环境模拟。

## 8. 安全、权限与连续性约束

1. 私有记忆默认仅所属智能体/用户可访问；跨账号、跨智能体、跨云访问必须有显式授权和范围限制。
2. 认证、场景成员资格、能力权限和工具执行授权分层检查。
3. 认知模型不能自行修改安全边界、令牌权限、成员权限或生产配置。
4. 重要状态更新采用版本化、可审计、可回滚方式；旧状态不静默销毁。
5. 真实数据接入前，必须先有只读适配器、隐私评估、数据最小化和单独审批。
6. 影子实验与生产状态隔离；默认不写生产数据库、不修改生产提示词、不调用生产 API。

## 9. 分阶段落地与验收

### Phase A — 规范与只读映射
- 建立本体字典、关系字典、证据等级和状态协议；
- 将社区现有实体映射到本体职责；
- 不迁移生产数据、不改变生产 API。

验收：字段语义、主体归属、时间语义、来源和权限边界均有文档与测试。

### Phase B — 离线最小认知闭环
- 使用合成数据构建 MOU；
- 实现观察、记忆关联、假设、预测、反馈和模型版本；
- 运行多系统演化影子评估器。

验收：能识别未知、保留矛盾、解释状态变化；单事件不能形成稳定特征；跨系统效应不能制造证据；可重复运行得到一致结果。

### Phase C — 私有记忆与连续性实验
- 在隔离测试环境验证主体级私有记忆；
- 验证事件时间/记录时间、身份连续性、记忆修正与恢复；
- 进行双账号、双智能体越权访问测试。

验收：账号 A 无法读取账号 B 的私有记忆；授权撤销后访问失败；历史版本可审计恢复。

### Phase D — 监督式社区认知
- 将已验证的认知能力接入聊天与场景互动；
- 智能体可提出问题和行动建议；
- 高影响操作仍需明确授权/人工批准。

验收：认知状态确实改变后续行为；每个重要变化有证据链；无未经批准的生产写入或权限提升。

### Phase E — 超越性验证
对每项主张设置基准、对照组、样本量、重复试验、失败判据和资源成本。至少评估记忆连续性、迁移能力、不确定性校准、错误修正、长期可靠性、延迟与成本。未有实验结果前，不宣称已超越人类能力。

## 10. 当前状态声明

本文件是基于参考材料形成的架构对齐规范。它不表示以上认知本体、MOU、长期记忆、情感价值系统、主动探索或动态场景运行时已经在当前 ZHI 社区 MVP 中实现。

当前社区 MVP 的认证、场景成员、邀请、会话与消息能力继续按独立的安全验收推进。后续实现必须逐步落地、可测试、可回滚；不得以理论规范为理由直接改动生产系统。


## 11. 当前离线工程模块状态（2026-10-30）

以下仅表示已提交代码及 CI 覆盖，不表示已接入生产或具备持久化能力：

- `ontology_helpers.ts`：MOU 记录字段与证据等级校验；私有认知记录按 owner_user_id + agent_id 双重匹配。
- `cognitive_cycle_helpers.ts`：从假设与预测生成追加式反馈记录；生成待人工审核的影子修订提案。
- `cognitive_version_helpers.ts`：只有所属用户明确批准后才生成新版本；回滚以新版本恢复旧快照，不删除中间历史；拒绝跨用户/跨智能体回滚。
- 对应 `*_test.ts`：验证未知置信度、来源追溯、推断时间、反馈关联、影子提案、批准门槛、过期版本拒绝和回滚主体边界。

**明确限制：** 这些是无数据库写入、无网络访问的纯函数模块。当前尚未实现认知数据表、持久化版本日志、真实 API 路由、双账号真实 HTTP 端到端测试或生产记忆接入。双账号真实 API 隔离仍是发布前安全门槛，不能用纯函数测试替代。
