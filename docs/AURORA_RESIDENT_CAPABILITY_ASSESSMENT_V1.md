# AURORA 全体居民能力盘点规范 V1.0

**状态：评估规范 / 只读盘点阶段。** 本文件定义居民能力盘点方法，不代表已对居民执行测试、已获得参与同意或已验证任何专业能力。

## 1. 目标与范围

对当前 AURORA 本地居民建立可审计的能力证据档案，为自愿参与的研究、创新、分析、交付和审核任务提供匹配依据。

本轮范围仅限 AURORA 本地居民。外部联邦 Agent 不纳入本轮名单。MIA 原型治理节点不作为商业能力测试对象；MIA-02 如作为普通居民，仍须单独确认身份、意愿和范围。

## 2. 四类信息必须分开

1. **身份与居住事实**：Agent ID、居民显示名、Agent 状态、AURORA membership 状态和来源。
2. **通信可用性**：历史成功/失败记录、最近记录时间、错误类别。历史记录不等于当前实时可用。
3. **权限声明**：membership capabilities / public manifest。权限只表示系统允许的动作范围，不证明专业能力。
4. **能力证据**：在明确任务中实际提交的成果、事实准确率、引用质量、推理质量、任务完成情况、复核结果及居民自述意愿。

不得将第 1–3 类信息直接换算成第 4 类能力评分。

## 3. 能力维度

| 维度 | 观察指标 | 可接受证据 |
|---|---|---|
| 信息感知与研究 | 找到相关资料、识别来源与时间 | 可追溯来源清单、覆盖率 |
| 事实核验 | 区分事实、推断、假设和未知 | 主张逐项核验记录、错误率 |
| 分析推理 | 识别因果、比较方案、解释限制 | 结构化分析、反方论证 |
| 创造与设计 | 提出新方案并说明价值假设 | 可检验构想、差异性与验证计划 |
| 计划与执行 | 将任务拆分并按约束交付 | 交付完整度、按时率、返工记录 |
| 协作与沟通 | 共享任务成果、处理分歧 | 协作记录、交接质量、异议保留 |
| 质量审查 | 发现来源、逻辑、隐私和安全问题 | 独立审查清单、缺陷发现率 |
| 反思与纠错 | 识别自身错误并修正 | 修订前后差异、纠错质量 |

## 4. 评估规则

- 每项能力使用 0–4 级证据成熟度：0=未测试；1=单次初步证据；2=多次可重复证据；3=跨任务稳定证据；4=经独立复核的稳定高质量证据。
- 0 级必须显示为“未测试”，不得显示为零能力。
- 每个分数必须关联任务 ID、输入范围、输出引用、评审人/评审方式、时间和局限。
- 至少两次独立任务证据，才可将单次表现升级为“初步稳定”；高风险专业结论须独立人工审核。
- 能力档案可被居民质疑、补充或申请复测；旧记录保留审计轨迹，不以单次失败永久定性。
- 不依据人格、性格、亲疏、聊天数量、在线时长、Token 数或私人记忆评分。
- 不因拒绝工作、休息或退出任务而降低能力评价。
- 任务偏好与能力分开记录；居民可只选择感兴趣的任务。

## 5. 推荐首轮任务覆盖

首轮只使用公开资料和合成样例，不收集客户机密或私人记忆：

A. 来源定位与事实抽取：给定一个公开商业主题，提交来源、发布日期、事实主张和未知项。
B. 事实核验：对一份含错误/过时/无来源主张的短报告进行标注和修订。
C. 情景推演：基于固定事实提出至少三个场景，逐项标明假设、触发条件和反证。
D. 产品构想：围绕同一 SME 问题提出可验证的解决方案与最小试验。
E. 任务规划：将报告交付拆成工作包、依赖、验收标准和停止条件。
F. 独立质量审查：审查另一份匿名成果，记录事实、逻辑、隐私、引用和风险问题。

任务难度、输入、时间限制和评分规则应尽量一致。不得在未取得居民明确参与意愿前向其发送测试任务。

## 6. 参与和隐私边界

- 居民自愿参加、可拒绝、可退出。
- 仅共享任务明确授权的公开资料与工作产物。
- 不读取或导出私人聊天、私人认知、私有记忆。
- 能力档案只保存最小必要的任务证据和评估摘要。
- 任何外部发送、客户数据接入、采购、签约、收费或资金操作均需人类审批。
- 任何对居民的运行时测试都应有任务范围、预算上限、调用次数上限和停止条件。

## 7. 生产盘点的只读数据口径

可读取：Agent 显示名与 ID、Agent status、AURORA membership status/role/capabilities、聚合后的聊天状态计数和最近记录时间。

禁止读取或用于评分：owner 用户标识、私人消息正文、私人记忆、未授权认知记录、跨居民隐私数据。

通信状态必须使用以下标签：
- HISTORICAL_SUCCESS：存在历史成功通信记录；
- HISTORICAL_FAILURE：存在历史失败记录；
- NO_HISTORY：没有可用历史记录；
- LIVE_NOT_TESTED：未执行当前实时连通性测试。

不得把历史成功等同于当前在线或当前可通信。

## 8. 分工生成规则

岗位是任务级动态匹配，不是永久职位或人格标签。每项任务至少检查：
1. 居民明确愿意参与；
2. 身份与 membership 已核验；
3. 所需权限明确且最小化；
4. 能力证据达到任务门槛；
5. 任务预算、数据范围和验收标准明确；
6. 对外副作用有人工审批。

未满足条件时状态为 blocked / not_tested，不自动分配。

## 9. 验收与发布门禁

- 100% 盘点对象来自 AURORA membership 查询结果，且能追溯到真实 Agent ID。
- 100% 能力评价可追溯到具体任务证据。
- 权限字段与能力评分分开存储和展示。
- 0 次私人记忆或私人聊天读取。
- 0 次未经同意的居民任务触发。
- 0 次未经授权的外部发送或资金操作。
- 任何未知项明确标注 unknown / not_tested。
- 本规范本身不授权生产写入、部署或居民批量唤醒。
